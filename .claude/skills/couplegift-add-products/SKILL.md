# 선물 상품 추가 (쿠팡 파트너스 링크 생성)

파트너스 API 는 최종 승인 전이라 못 쓴다. 그래서 파트너스 사이트에서 간편링크를 만들어 `src/data/coupang/curated.json` 에 넣어 두고, 추천 API(`src/app/api/recommendations/route.ts`)가 이 목록에서 모델이 고른 상품에 그 링크를 건다. 목록에 없는 선물은 지금처럼 쿠팡 검색 링크(수수료 없음)로 나가므로, 목록이 넓을수록 수익 링크 비율이 올라간다. 이 스킬은 `threads-coupas` 저장소의 `threads-add-products` 스킬을 CoupleGift 용으로 옮긴 것이다.

## 0. 할 수 있는 환경인지 먼저 확인
- 링크는 **사용자 Chrome 의 쿠팡 파트너스 로그인 세션**으로만 만든다. `chrome-browser` 스킬을 먼저 읽고 Claude in Chrome 도구(`mcp__claude-in-chrome__*`)를 불러온다.
- 브라우저 도구가 없으면 (클라우드 세션 등): 링크를 지어내지 않는다. 고를 상품 종류·검색어 목록만 만들어 주고, "데스크톱 앱에서 Chrome 을 연결한 세션으로 다시 요청하거나, 링크를 직접 만들어 `카테고리 | 상품명 | https://link.coupang.com/a/...` 형식으로 보내 달라"고 안내한다.
- 로그인이 안 돼 있으면 사용자에게 로그인을 부탁하고 기다린다. 비밀번호를 대신 입력하지 않는다.

## 1. 몇 개, 무엇을 고를지
- **개수:** 요청한 만큼. 정해지지 않았으면 카테고리마다 3~5개씩 (총 20~30개). 현재 `curated.json` 을 먼저 읽어 이미 있는 상품·카테고리와 겹치지 않게 한다.
- **카테고리 분포:** 폼의 선호 카테고리와 맞춘다 — 액세서리/주얼리, 뷰티, 향수·캔들, 전자기기, 패션·잡화, 리빙, 식품·디저트, 문구·도서, 커플 아이템. 한쪽으로 쏠리지 않게 한다.
- **예산 분포:** 1만~3만 / 3만~5만 / 5만~10만 / 10만 이상 구간이 모두 있어야 예산 필터(`buildCuratedPromptList`)가 쓸모 있다. 3만 원 미만은 수수료가 작으니 전체의 20% 이하로.
- **고르는 기준:**
  - 기념일 선물로 어색하지 않은 물건 (생일, 100일, 기념일, 크리스마스 등). 실사용 소모품·건강·의료·성인용품은 뺀다
  - 후기 많은 대표 상품, 판매 종료·품절 아님, 이미지가 깨끗한 상품
  - 성별을 가리지 않는 것과 한쪽에 맞춘 것을 섞고, 맞춘 것은 `note` 에 "여성용"처럼 적는다

## 2. 링크 만들기 (Chrome)
1. `https://partners.coupang.com/#affiliate/ws/link/0/<검색어>` 로 검색한다 (검색어는 URL 인코딩).
2. 기준에 맞는 상품을 고르고, 그 상품의 링크 생성 버튼(`.btn-generate-link`)을 누른다.
3. 페이지에 나타난 `https://link.coupang.com/a/...` 와 상품명, 판매가, 상품 이미지 주소(https)를 읽는다.
4. 여러 개를 한 번에 돌릴 때: **JS 반복문은 비동기로 시작하고 결과를 폴링**한다 (한 번의 JS 실행은 45초 제한). 반복문을 겹쳐 실행하면 결과가 섞이니, 하나가 끝난 뒤 다음을 시작한다.
5. 같은 상품에 링크를 두 번 만들지 않는다. 링크에 직접 접속하거나 `curl` 로 확인하지 않는다 (가짜 클릭으로 잡힌다).

## 3. 사용자 승인 (등록 전에 반드시)
아래 표를 보여 주고 승인받는다. 빼거나 바꾸라고 하면 그대로 따른다.

| # | 카테고리 | 상품명 | 가격 | 링크 | 고른 이유 |
|---|---|---|---|---|---|

## 4. curated.json 에 추가
`src/data/coupang/curated.json` 의 `items` 배열 끝에 추가하고 `updatedAt` 을 오늘 날짜(YYYY-MM-DD)로 바꾼다.

```json
{
  "id": "g001",
  "name": "쿠팡 상품명 그대로",
  "category": "액세서리",
  "link": "https://link.coupang.com/a/xxxxxx",
  "price": 39000,
  "image": "https://thumbnail...coupangcdn.com/....jpg",
  "note": "여성용, 은 소재, 기념일 선물용"
}
```

- `id`: `g` + 3자리 번호, 기존 번호와 겹치면 안 된다 (다음 번호 사용).
- `link`: 파트너스 간편링크만 (`link.coupang.com`, `coupa.ng`). 이 밖의 주소는 로드할 때 조용히 버려진다. 파라미터를 붙이거나 바꾸지 않는다.
- `price`: 읽은 판매가(원, 정수). 모르면 생략 — 그러면 카드는 AI 예상 가격으로 표기된다.
- `image`: 상품 이미지 https 주소. 모르면 생략 — 카테고리 이모지 박스가 나온다.
- `note`: 모델이 고르기 쉽게 하는 짧은 설명(60자 이내): 대상 성별·분위기·상황. 상품 상세 문구를 그대로 옮기지 않는다.

## 5. 확인 후 올리기
```bash
node scripts/check-curated.mjs     # id 중복, 링크 도메인, 가격 형식 검사
npx tsc --noEmit                   # 타입 검사 (node_modules 가 있을 때)
```
- 커밋 메시지에 몇 개를 어떤 카테고리 위주로 넣었는지 적는다. push 와 PR 은 사용자가 요청했을 때만 한다.
- 배포(main 병합) 후 새 추천부터 반영된다. 카드 버튼이 "쿠팡에서 보기" 이면 등록 상품이 걸린 것이고, "쿠팡에서 검색" 이면 목록에 맞는 상품이 없어 일반 검색 링크로 나간 것이다.

## 함정
- 링크를 지어내거나 다른 사람의 링크를 쓰지 않는다. 수익이 안 잡히고 정책 위반이 된다.
- 목록이 비어 있으면(items 가 0개) 코드는 기존 동작(카탈로그 → API → 검색 링크)으로 그대로 동작한다. 깨지지 않는다.
- 품절·판매 종료 상품은 빼고 같은 종류의 다른 상품으로 교체한다. 몇 달에 한 번 목록을 훑어 죽은 링크를 정리한다.
- 가격은 쿠팡에서 수시로 바뀐다. 카드에는 "쿠팡 판매가 · 변동될 수 있음"으로 표기되니 가격을 단정하는 문구를 `note` 에 쓰지 않는다.
